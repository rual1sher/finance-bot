# AGENTS.md — Инструкции для AI-агентов (Antigravity)

## 1. О проекте (Project Mission)
**Finance Bot** — приватный автономный Telegram-бот для персонального учёта финансов и расходов.
- **Главная цель**: взять под контроль ежедневные импульсивные расходы (такси, кафе/завтраки, свидания, супермаркеты), накопление денег и детальная аналитика за неделю и месяц.
- **Принцип приватности**: данные принадлежат исключительно владельцу, хранятся локально в файле SQLite и никогда не передаются на сторонние серверы.

---

## 2. Стек технологий и архитектура
- **Среда выполнения**: Node.js (версия 22+ или 26+) + TypeScript (`tsx`, `typescript`) с поддержкой ES Modules (`"type": "module"` в `package.json`).
- **Telegram фреймворк**: `telegraf` (v4.x).
- **База данных**: Локальная SQLite через встроенный модуль `node:sqlite` (`DatabaseSync`). Хранилище в одном файле `finance.db`.
- **Конфигурация**: `dotenv` (`.env` файл: `BOT_TOKEN`, `ADMIN_ID`).

---

## 3. Критические правила для агентов (Agent Guidelines)

> [!CAUTION]
> ### Правило №1: Никаких несогласованных команд в терминале
> Никогда не дергать bash/терминал (`python3`, `node`, `npm`, `bash` и т.д.) без явного согласия или прямой команды пользователя.
> Всю работу с кодом вести через создание и редактирование файлов (`write_file`, `edit_file`).

> [!IMPORTANT]
> ### Правило №2: Строгая приватность и безопасность
> Бот предназначен строго для одного владельца.
> Все входящие сообщения ОБЯЗАНЫ проходить проверку через middleware:
> `ctx.from.id === Number(process.env.ADMIN_ID)`.
> Чужие пользователи получают уведомление: «Это личный конфиденциальный бот. Доступ ограничен.» и их запросы не обрабатываются.

> [!TIP]
> ### Правило №3: Стиль кода и согласованность
> - Модульная структура (отдельно клавиатуры, база данных, обработчики, генераторы отчётов).
> - Понятные названия функций и переменных.
> - Типы и интерфейсы, используемые более чем в одном файле, обязательно выносятся в папку `src/type/`.
> - Обязательная обработка ошибок `try/catch` во всех асинхронных хэндлерах бота.
> - Логирование ключевых действий в консоль (`console.log`, `console.error`).

> [!IMPORTANT]
> ### Правило №4: Минимализм в эмодзи
> Использовать эмодзи максимально мало — исключительно для упрощения визуального восприятия интерфейса (например, функциональные маркеры категорий или кнопок). Полностью исключить приветственные, эмоциональные эмодзи и смайлы (👋, 😊, 🚀 и т.п.) как в тексте бота, так и в ответах ассистента. Тексты должны быть строгими и лаконичными.

## 4. Пользовательский интерфейс (UX) и логика работы

1. **Ввод суммы (число):**
   - Пользователь присылает число со строгим указанием знака операции:
     - **Расход** (со знаком `-`): например, `-40k`, `-35000` или `-1.5kk`.
     - **Прибыль / Доход** (со знаком `+`): например, `+40k`, `+500k`, `+2kk` или `+1000000`.
   - Поддерживаются латинские множители: `k` (* 1 000) и `kk` (* 1 000 000). Минимальная сумма: 1 000.
   - Числа без знака `+` или `-` отклоняются (бот выводит подсказку с примерами).
   - Бот мгновенно отправляет Inline-клавиатуру с сохранёнными категориями пользователя соответствующего типа (расходные или доходные) и кнопкой `[ ✏️ Ручное ]`.
   - Пользователь может выбрать категорию нажатием или нажать `Ручное`, ввести своё название (например, `Аптека` или `Премия`) — категория автоматически сохранится в базу с нужным типом и в следующий раз будет отображаться среди готовых кнопок.

2. **Отчёты:**
   - Кнопки `📊 Отчёт за неделю` и `📅 Отчёт за месяц`:
     - Доход и Расход за период.
     - Сальдо (Доход минус Расход).
     - Разбивка расходов по категориям с процентами и суммами.

3. **Отмена и удаление записей:**
   - Инлайн-кнопка под каждым подтверждением операции для мгновенной отмены ввода.
   - Кнопка `🕒 История` (или команда `/history`): просмотр операций с пагинацией (`[ ⬅️ Назад ]`, `[ 1/4 ]`, `[ Вперёд ➡️ ]`) и инлайн-кнопками `[ ❌ 1 ]`...`[ ❌ 5 ]` для быстрого удаления любых записей.

## 6. Схема базы данных (SQLite)

```sql
CREATE TABLE IF NOT EXISTS transactions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL,
    amount REAL NOT NULL,
    category TEXT NOT NULL,
    type TEXT NOT NULL DEFAULT 'expense', -- 'expense' или 'income'
    comment TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE IF NOT EXISTS categories (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL,
    name TEXT NOT NULL,
    icon TEXT,
    type TEXT NOT NULL DEFAULT 'expense',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(user_id, name, type)
);

CREATE TABLE IF NOT EXISTS pending_expenses (
    id TEXT PRIMARY KEY,
    user_id INTEGER NOT NULL,
    amount REAL NOT NULL,
    type TEXT NOT NULL DEFAULT 'expense',
    comment TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```
